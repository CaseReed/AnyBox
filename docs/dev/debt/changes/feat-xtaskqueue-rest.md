# xgameruntime

## add Functional

- [XTaskQueueCreateComposite](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - follows the public libHttpClient `TaskQueue.cpp` and `TaskQueueTests.cpp`, not a console: a composite shares the ports it is built from and keeps their queues alive; terminating any queue cancels only the callbacks, delayed callbacks and waiters submitted through it; a null output pointer returns `E_POINTER` where the reference does not check it; a port handle that is null, not returned by `XTaskQueueGetPort`, or whose queue was released returns `E_GAMERUNTIME_INVALID_HANDLE` (`0x8924010C`, from the public GDK error code list), checked against the live ports without reading the handle
  Closes when: measured on a console title
- [XTaskQueueGetPort](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - a null output pointer returns `E_POINTER` and an invalid port `E_INVALIDARG`; the reference writes through the pointer unchecked
- [XTaskQueue](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - `XTaskQueueGetPort`, `XTaskQueueRegisterMonitor`, `XTaskQueueUnregisterMonitor`, `XTaskQueueRegisterWaiter` and `XTaskQueueUnregisterWaiter` use the process task queue for a null queue, as the other XTaskQueue exports do; the reference dereferences the null handle
- [XTaskQueue](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - a queue with callbacks still queued is kept alive until they run or its termination cancels them, as in the reference; closing the last handle of a manual queue with undispatched callbacks therefore keeps the queue and its waiters
- [XTaskQueueRegisterMonitor](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - each monitor is called once for every port role its queue gives the port a callback was queued on, after the callback is queued (for a delayed callback, when the delay elapses; for a waiter, when its handle is signaled) and before an immediate port runs it; termination calls no monitor, where the reference calls them once per port when it queues the termination and once for every canceled delayed callback and waiter it moves into the queue; there is no limit on the number of monitors, the reference returns `E_OUTOFMEMORY` past 32; registering a monitor, or unregistering another one, from inside a monitor callback works, where the reference waits forever; the queue handle given to a monitor lives as long as the queue, and closing it stops with `AbxUnsupported`
  Closes when: measured on a console title
- [XTaskQueueUnregisterMonitor](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - waits for the calls of that monitor already running on other threads, where the reference waits for any monitor call on the queue; unregistering a monitor from inside its own callback stops with `AbxUnsupported`, the reference waits forever; an unknown token does nothing
- [XTaskQueueRegisterWaiter](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - built on a thread-pool wait: each signal queues the callback once and the wait is armed again after it returns, so a manual-reset event left signaled fires again; a signal whose callback cannot be queued on a live queue is dropped and the wait armed again, as in the reference; a callback already queued when the waiter is unregistered still runs; termination calls each waiter that has no callback queued once with `canceled = true`; closing a queue unregisters its waiters without calling them; there is no limit on the number of waiters, the reference returns `E_OUTOFMEMORY` past 60 per port; a null callback or token returns `E_POINTER`, an invalid port or null handle `E_INVALIDARG`, a terminated queue `E_ABORT`
  Closes when: measured on a console title
- [XTaskQueueRegisterWaiter](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - a handle signaled as an abandoned mutex stops with `AbxUnsupported`; the reference ignores that signal and never arms the wait again, which leaves the waiter registered but dead without telling the title
  Closes when: the console behaviour for an abandoned mutex is measured

## change [pending and delayed callbacks are invoked]

- [XTaskQueueTerminate](../../../core/libs/xdll/xgameruntime/TaskQueue.cpp) (xgameruntime) - pending, delayed and waiter callbacks are invoked with `canceled = true` on the terminating thread, not on their port's dispatcher; waiting from inside a callback submitted through that queue stops with `AbxUnsupported`, whichever port runs it (thread pool, manual dispatch or immediate) and also from a callback nested inside it on the same thread; a callback submitted through another queue sharing the port may wait, because termination does not wait for it
