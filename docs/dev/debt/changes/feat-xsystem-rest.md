# xgameruntime

## add Functional

- [XSystemGetAppSpecificDeviceId](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - 44 uppercase hexadecimal digits and a terminator: the first 22 bytes of a SHA-256 over a fixed AnyBox prefix, the host's `MachineGuid` (`HKLM\SOFTWARE\Microsoft\Cryptography`) and the `<TitleId>` of `MicrosoftGame.config`, so the value is stable for one title on one Windows installation, differs between titles and does not show the machine GUID; it changes when Windows is reinstalled, and the console's format is not documented beyond its length; `XSystemAppSpecificDeviceIdBytes` (45, counting the terminator) comes from the MIT-licensed Microsoft XBOX-GDK-dotnet bindings; a buffer smaller than that returns `HRESULT_FROM_WIN32(ERROR_INSUFFICIENT_BUFFER)` without touching `appSpecificDeviceIdUsed`, which otherwise receives 45; the all-zero string the documentation gives for an error is never returned, because the documentation does not say which result comes with it, and a machine GUID that cannot be read or hashed stops with `AbxUnsupported` instead; a null `appSpecificDeviceId` or a missing `<TitleId>` stops with `AbxUnsupported`
  Closes when: the console's format and the size reported in `appSpecificDeviceIdUsed` are measured on a console
- [XSystemGetAnalyticsInfo](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - for a title whose `XSystemGetDeviceType` is `Pc`, `osVersion` and `hostingOsVersion` are both the host Windows version (major, minor and build from `RtlGetVersion`, the update build revision `UBR` as `revision`), as the documentation says for desktop devices, and `family` is `Windows`, the documentation's example; `form` is empty, because the string a desktop reports is not documented; an XboxOne or Scarlett title stops with `AbxUnsupported`, because the title OS version and form string a console reports are not documented
  Closes when: the desktop `form` string and the values a console reports are measured
- [XSystemGetRuntimeInfo](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - for a `Pc` title, `runtimeVersion` and `availableVersion` are zeros, the documented value when the gaming runtime service is not installed: the title runs on AnyBox, not on that service; a title that refuses to start without it is not served; an XboxOne or Scarlett title stops with `AbxUnsupported`, because a console always reports its runtime version and AnyBox has none
  Closes when: a title is reported that checks the runtime version
- [XSystemAllowFullDownloadBandwidth](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - does nothing: the documentation calls it a signal the system may disregard, and the host has no download throttling to lift; the documentation lists Xbox Series consoles as the only supported platform, and the no-op is applied to every title, including PC and XboxOne titles for which it documents nothing; declared `void` as on the documentation page, although the MIT-licensed XBOX-GDK-dotnet bindings declare an `int` result
  Closes when: the return type is confirmed against a console title
- [XSystemHandleTrack](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - a null callback, which disables tracking, returns `S_OK`; a non-null callback stops with `AbxUnsupported`, because AnyBox reports no handle creation and destruction; the passive tracking the documentation describes (`XErrorReport` for invalid or leaked handles) is not done
  Closes when: the runtime's handles are tracked in one registry
- [XSystemIsHandleValid](../../../core/libs/xdll/xgameruntime/System.cpp) (xgameruntime) - a null handle returns `false`; any other handle stops with `AbxUnsupported`, because AnyBox keeps no registry of live handles and cannot tell a live handle from a freed one without reading it
  Closes when: the runtime's handles are tracked in one registry
