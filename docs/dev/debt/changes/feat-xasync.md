# xgameruntime

## add Functional

- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - return codes follow the public libHttpClient `AsyncLib.cpp`, `AsyncBlockTests.cpp` and `pal.h`, not a console: `XAsyncBegin` on a block in use returns `E_INVALIDARG`; a null queue with no process task queue returns `E_NO_TASK_QUEUE` (`0x800701AB`) and an allocation failure `E_OUTOFMEMORY`, both also left as the block's status; a failed `Begin` op completes the call with its error; `XAsyncSchedule` while work is already scheduled returns `E_UNEXPECTED`, after a failure returns that failure, and after a success without payload, or once the result was retrieved, returns `E_INVALIDARG`; a `DoWork` that returns success without completing completes with `E_UNEXPECTED`, and scheduled work is skipped once the call completed without payload; a second `XAsyncGetResult` returns `E_ILLEGAL_METHOD_CALL`, and a wrong identity, null buffer or too small buffer returns `E_INVALIDARG` or `E_NOT_SUFFICIENT_BUFFER` and discards the result; `XAsyncRun` work cannot be canceled
  Closes when: measured on a console title
- [XAsyncCancel](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - invokes the provider's `Cancel` op only while the call's status is `E_PENDING`, following `XAsync.h` ("does nothing if the call has already completed"); the reference `AsyncLib.cpp` still invokes it on a call that completed with a payload not yet retrieved
  Closes when: measured on a console title
- [XAsyncSchedule](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - when the task queue refuses the work, it returns the queue's error and leaves no work scheduled, so the next `XAsyncSchedule` on that call submits again and returns the queue's error, not `E_UNEXPECTED`; the reference `AsyncLib.cpp` keeps its scheduled flag set after a failed submit, so its next `XAsyncSchedule` returns `E_UNEXPECTED`
  Closes when: measured on a console title
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - the provider's `Cleanup` op runs once, when the last reference to the call is released (after the op or completion callback that ended it, or after `XAsyncGetResult`), never during another op; the reference can run it earlier, at the end of the `DoWork` that completed the call
  Closes when: the op order is measured on a console
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - when the completion callback cannot be queued because the call's task queue was terminated, it stops with `AbxUnsupported`, naming the XAsync export on the stack (`XAsyncComplete`, or `XAsyncBegin` for a failed `Begin` op), or `XAsyncComplete` when the completion starts from a task queue callback (work canceled by `XTaskQueueTerminate`, or work whose result is not `E_PENDING`); the reference holds termination until outstanding calls complete, which AnyBox's XTaskQueue cannot do
  Closes when: XTaskQueueTerminate waits for outstanding async calls
- [XAsyncBegin](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - does not return `E_ABORT` up front when the block's queue is already terminated, as the reference does: XTaskQueue exposes no termination state, so the `Begin` op runs and `XAsyncSchedule` returns the queue's `E_ABORT`; when the `Begin` op returns that failure, `XAsyncBegin` returns `S_OK` and the call completes with `E_ABORT` if the block has no completion callback, and stops with `AbxUnsupported` in `XAsyncBegin` if it has one
  Closes when: XTaskQueueTerminate waits for outstanding async calls
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - a null async block, provider, work callback or result size pointer stops with `AbxUnsupported`, except `XAsyncComplete` with `E_PENDING`, which returns first; a block whose internal bytes are all zero behaves as a zeroed block in the reference: `XAsyncCancel` and `XAsyncComplete` do nothing, `XAsyncGetStatus`, `XAsyncGetResultSize` and `XAsyncGetResult` return `S_OK` with a size of 0, and `XAsyncSchedule` returns `E_INVALIDARG`; on any other block that no call owns, `XAsyncCancel` and `XAsyncComplete` do nothing, as in the reference, and `XAsyncGetStatus`, `XAsyncGetResultSize`, `XAsyncSchedule` and `XAsyncGetResult` stop with `AbxUnsupported`, because the reference returns whatever its status field holds
- [XAsyncGetStatus](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - waiting from inside the call's own completion callback returns the status at once instead of waiting for that callback to return
- [XAsync](../../../core/libs/xdll/xgameruntime/Async.cpp) (xgameruntime) - a completion callback still queued when its task queue is terminated runs the title's callback on the terminating thread, as the reference does for canceled completions
